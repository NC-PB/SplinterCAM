# AQ-010: Which module refuses a rapid into the stock when the link height itself is wrong (plan 0007, steps 4 and 5)

- Asked: 2026-10-27, plan 0007 step 4 (`cl` implementation, cnc-reviewer finding), by the coding agent (headless run)
- Box: 1 (Peter's judgement: machine safety, and the interface between `cl` and `toolpath`/`strategies/profile`)
- Question: `cl` checks every RAPID against the link height the producer writes into the record (REQ-CL-011, D-062, D-087): a rapid never ends below its link height, and one that moves in X or Y never starts below it. `cl` does not know the stock or the retract height h_r, so it cannot tell whether the link height is right. The Reviewed SPEC gives research 10 test 1 (no RAPID in the plane below h_c; no move below h_r inside the stock box grown by R) to step 5 (`src/splintercam/cl/SPEC.md`, Scope, "Out"). If the producer has a bug that copies the target Z into the link height, this record passes every check of `cl` today (clearance 5):
  - RAPID (NaN, NaN, 50), link 50; RAPID (−10, 0, 5), link 5; RAPID (−10, 0, 3), link 3;
  - **RAPID (20, 0, −3.333), link −3.333**: a diagonal G0 from the approach point into the stock at cut depth;
  - LINE (60, 0, −3.333) CUT; RAPID (60, 0, 50), link 50.
  On the machine: the tool rapids into the material, breaking the tool and maybe damaging the part or the fixture. Options:
  - (a) Keep it in step 5, as the SPEC has it. Step 5's SPEC gets a tagged requirement and test for research 10 test 1 (no RAPID in the plane below h_c in this slice, and no move below h_r inside the stock box grown by R), checked on the record before it is handed to `ncx`. `cl` stays unchanged. Risk: until step 5 is merged and reviewed, only the producer's own correctness stands between a wrong link height and the machine. No NCX is written before step 6, so nothing reaches a machine in between.
  - (b) Tighten `cl` as well, a SPEC change: add `retract_height_mm` (h_r) to `ClHeader`; refuse a RAPID that moves in X or Y below `clearance_height_mm`, and any RAPID that ends below h_r (research 10, Method 5: in plan 0007 every link height is h_c or h_r). About 15 NLOC more by the 1.5 rule, within the budget 310 (about 250 used). It restricts the record to clearance-height links in the plane; later plans with lower links (D-087) would loosen it through a new SPEC entry.
  - (c) Both.
- Recommendation: (c). (a) is the real check, since only step 5 knows the stock. (b) is cheap and stops the most dangerous producer bug, a G0 in the plane below the clearance height, at the last module before the writer, for as long as plan 0007 has clearance-height links only. Safe default meanwhile: `cl` is implemented as the Reviewed SPEC says (option (a) on the `cl` side). Nothing is written to NCX until step 6, and step 5 is not started in this run.
