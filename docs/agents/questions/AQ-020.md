# AQ-020: Should toolpath refuse a plan whose tool is not the header's tool (plan 0007, step 5)

- Asked: 2026-10-27, plan 0007 step 5 (`toolpath` implementation, cnc-reviewer finding 1), by the coding agent (headless run, lane E)
- Box: 1 (Peter's judgement: machine safety, and a new rule in the Reviewed `src/splintercam/toolpath/SPEC.md`)
- Question: `link_operation` refuses an approach point P within R of the stock box (REQ-TP-012), with R taken from `plan.tool` (DEC-TP-004: "a strategy bug cannot weaken the check"). The tool the machine loads is the header's `tool_number` (NCX `TOOL=`). Nothing compares the two. If a strategy or `job` bug hands over the Ø6 mill in the plan while the header calls T5, a Ø20 mill, P passes 3.6 mm (R 3 + 0.2·R) off the stock's side, and on the machine the Ø20 tool feeds down there with 6.4 mm of its radius inside the stock side, at the plunge feed and full depth: a side load the plunge was never planned for, likely a broken tool or a gouged part. Options:
  - (a) Add to REQ-TP-008: IF `plan.tool.number` differs from `header.tool_number`, THEN `link_operation` SHALL raise `ValueError` (after the three checks it has, in that order). About 3 NLOC; a unit test with T2 in the plan and T1 in the header. It catches a mixed-up tool, not a wrong diameter entered for the right number (that is the user's tool table, `model`).
  - (b) Leave it to `strategies/profile` and `job`, which build both from the same operation (DEC-TP-004's sentence then needs a correction: the check is only as good as the plan's tool).
- Recommendation: (a). It is cheap and makes DEC-TP-004's claim true. Safe default meanwhile: the Reviewed SPEC as it stands (no such check); nothing reaches a machine before steps 6 and 7, and the profile builds the header and the plan from one operation and one tool.
