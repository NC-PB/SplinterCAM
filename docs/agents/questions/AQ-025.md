# AQ-025: CI has no job that builds the pinned `ncx`, so the real-`ncx` test is skipped everywhere

- Asked: 2026-10-27, plan 0007 step 6 (`ncx` implementation, lane F), by the coding agent (headless run)
- Box: 1 (CI configuration is a protected path; the decision itself is Peter's already: plan 0007 question 3, `docs/research/27-machines-and-controllers.md`, The ncx call in plan 0007: "CI builds `ncx` from a pinned commit of NCXchange `main` (f74559c) in one job with the .NET SDK")
- Question: `src/splintercam/ncx/SPEC.md`, Test plan, says CI provides `ncx` and `SPLINTERCAM_NCXCHANGE`, so the real-`ncx` integration test (`tests/ncx/integration/test_real_ncx.py`) never skips there; it is the only check that the written words are valid NCX (REQ-NCX-001, 011; `.claude/rules/ncx.md`). `.github/workflows/check.yml` has no such step, and `ncx` is not on this Mac either. So today nothing has run the writer's text through `ncx format --check`, `check --strict` or `compile`: the canonical layout and `SPINDLE=OFF` (RR-006 items 1 and 3, DEC-NCX-008) are unchecked. On the machine: if NCXchange does not know `SPINDLE=OFF`, `check --strict` fails and `run_ncx` writes no program (safe, but the slice cannot produce one); if the layout differs, `format --check` fails the same way. Nothing wrong reaches a machine either way, because `compile` runs only after both pass (REQ-NCX-019), but step 7's end-to-end run would stop there.
- Recommendation: add the step to `.github/workflows/check.yml` (job `check`, before `check`, all three runners or at least `ubuntu-24.04`), in a pull request of its own:

  ```yaml
      - name: pinned ncx (plan 0007, question 3)
        if: steps.scope.outputs.full == 'true'
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          repository: NC-PB/NCXchange_
          ref: <the full SHA of f74559c>          # checkout needs the full SHA
          path: ncxchange
          token: ${{ secrets.NCXCHANGE_TOKEN }}   # only if the repository is private
      - uses: actions/setup-dotnet@<pinned SHA> # .NET 10, as research 26 built it
        if: steps.scope.outputs.full == 'true'
        with:
          dotnet-version: "10.0.x"
      - name: build ncx
        if: steps.scope.outputs.full == 'true'
        run: |
          dotnet publish ncxchange/src/Ncx.Cli/Ncx.Cli.csproj -c Release -o "$RUNNER_TEMP/ncx"
          echo "$RUNNER_TEMP/ncx" >> "$GITHUB_PATH"
          echo "SPLINTERCAM_NCXCHANGE=$GITHUB_WORKSPACE/ncxchange" >> "$GITHUB_ENV"
  ```

  The project path `src/Ncx.Cli/Ncx.Cli.csproj` and the loose `machines/` folder come from Project Spike (`plans/2026-10-02-ncxchange-drafts-D347-D371-answered.md`, the publish measured on f74559c); the executable's name `ncx` is assumed. Safe default meanwhile: the test is skipped with a visible message, as on a machine without `ncx`, and DEC-NCX-008 stays provisional. This pull request does not depend on the answer; step 7's end-to-end run does.
