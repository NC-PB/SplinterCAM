# AQ-027: Three small amendments to the Reviewed `ncx` SPEC that the implementation found

- Asked: 2026-10-27, plan 0007 step 6 (`ncx` implementation, lane F, spec-reviewer round), by the coding agent (headless run)
- Box: 1 (Peter's judgement: the public interface `job` uses, and the failure table of a Reviewed SPEC)
- Question: the code follows the readings below, recorded as DEC-NCX-011 and 012 (ours) in `src/splintercam/ncx/DECISIONS.md`; the spec review asks for the SPEC text to say so, which changes a Reviewed SPEC.
  1. **`NcxSection.last_line`** (Public interface). The SPEC says "1-based line before the next SECTION or the program end". The code ends the last section at its last move, so `COOLANT=OFF`, `SPINDLE=OFF`, `PROGRAM=END` and `FILE=END` belong to no operation and a message about them is located at `program` (DEC-NCX-011). Read literally, "the program end" could be `PROGRAM=END`, and the last operation would take in the spindle stop. For the user: a message about `SPINDLE=OFF` (RR-006) is shown against "program" rather than against the last operation. Proposed comment: `# 1-based line of its last move (DEC-NCX-011)`.
  2. **`TOL_BELOW_MINIMUM` and `TOL_ABOVE_MAXIMUM` from `write_ncx`** (failure table, REQ-NCX-017). `cl` accepts any tol above 0; an operation whose tol has no tolerance set (below 2/875 mm or above 1 mm) has no rounding allowance, so `write_ncx` returns no program with foundation's diagnostic at the operation, after its other errors (DEC-NCX-012). In plan 0007 `model` refuses such a tol first. Proposed: a failure-table row "A tol without a tolerance set (REQ-FND-010) | no program | `TOL_BELOW_MINIMUM`, `TOL_ABOVE_MAXIMUM` (error)", and in REQ-NCX-017 "…by move index, then the operation's tol".
  3. **Windows device names** (REQ-NCX-014). The SPEC lists COM1 to COM9 and LPT1 to LPT9. Microsoft's "Naming Files, Paths, and Namespaces" page, as the spec reviewer remembers it, now also lists COM0 and LPT0 (and the superscript digits, which the ASCII rule refuses already). Not checked here: no web access in this run. If so, `COM0` passes today; on Windows the compiled `COM0.h` could not be written. Proposed: add COM0 and LPT0 after checking the page.
- Recommendation: all three as proposed. Safe default meanwhile: the code as DEC-NCX-011 and 012 say, and the device list as the SPEC says. This pull request does not depend on the answers.
- Status: Answered 2026-10-27
- Answer: all three as proposed (Peter); COM0 and LPT0 are in Microsoft's list of reserved device names, add them.
