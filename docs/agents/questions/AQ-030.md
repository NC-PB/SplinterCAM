# AQ-030: A smallest step-down for the profile, so the pass count stays bounded (plan 0007, step 5)

- Asked: 2026-10-27, plan 0007 step 5 (`strategies/profile` implementation, simplifier round), by the coding agent (headless run, lane G)
- Box: 1 (Peter's judgement: which jobs the profile refuses, and a new rule in the Reviewed `src/splintercam/strategies/profile/SPEC.md`)
- Question: `stepdown_mm` is declared (0, ∞) (REQ-PRF-001), and the pass count is n = ⌈(z_top − z_bottom) / a_p,max⌉ (REQ-PRF-016). Nothing bounds n. A step-down typed as 0.0001 instead of 1 mm on a 10 mm deep profile gives 100 000 passes. The NC program becomes a few hundred MB, the run takes days, and the computer may run out of memory first. A step-down of about 1e-308 or less makes the quotient infinite, and `plan_profile` crashes with `OverflowError` instead of reporting a diagnostic. On the machine, the first case means hours of air cutting at the same contour, each pass a few µm deeper. Options:
  - (a) A declared smallest step-down (a value in `src/splintercam/foundation/tolerance_defaults.toml`, or the low end of `stepdown_mm`'s range, e.g. 0.01 mm), refused as `PROFILE_STEP_DOWN` like a step-down above the flute length (REQ-PRF-008). Simple; it catches unit mistakes (µm for mm).
  - (b) A declared largest pass count (e.g. 1000), refused as `PROFILE_TOO_MANY_PASSES` naming n. It bounds the output whatever the depth, but the number has no machining meaning.
  - (c) Leave it: refuse only the overflow, as a diagnostic.
  The same overflow comes from depths whose difference is not finite (z_top 1e308, z_bottom −1e308; spec review): it happens inside REQ-PRF-005's check, before `PROFILE_BELOW_STOCK` could report. Under (a) or (b) a non-finite quotient would be refused by the same code.
- Recommendation: (a), with the value Peter names (0.01 mm suggested: below that a profile step-down is a typing error on any mill of the slice). It is one comparison in REQ-PRF-008 (about 2 NLOC and a unit test), and the declared range then holds the limit (D-049). Safe default meanwhile: the Reviewed SPEC as written. No check is added; the gap is listed in `src/splintercam/strategies/profile/AGENTS.md`, Known pitfalls, and in the pull request. In plan 0007 the step-down is typed by Peter for the dry run (step 8).
- Status: Answered 2026-10-27
- Answer: (a) with 0.01 mm (Peter): a step-down below 0.01 mm is refused as PROFILE_STEP_DOWN; the declared range of stepdown_mm starts at 0.01 (D-049). A non-finite pass quotient is refused by the same check.
