# AQ-040: The NC program left in the output folder by a run that `--strict` fails (cnc review of `apps/cli`, plan 0007 step 7)

- Asked: 2026-10-30, plan 0007 step 7 (`apps/cli` implementation, lane I), by the coding agent (headless run)
- Box: 1 (Peter's judgement: what reaches the machine; changes to the Reviewed SPECs of `job` and `apps/cli`)
- Question: AQ-036 item 1 (a) left warnings from `io` and `model` (`DXF_GAP_CLOSED`, `DXF_SKIPPED`, `TOOL_POINT_ABOVE_FLUTE`) and `JOB_MACHINE_OVERRIDDEN` to the operator, with `splintercam run --strict` turning them into a failing exit code. The cnc review of `src/splintercam/apps/cli/` found that `--strict` changes only the exit code: `run_job` does not know about it, a WARNING never stops the run (`src/splintercam/job/_run.py`, `_Run.poll`), so after a clean `ncx` compile `RECT_FILLETS.h` is moved into the output folder anyway. The CLI then exits 1, prints no path on stdout, and with `--json` says `"ncx_file": null, "nc_files": []`, while `RECT_FILLETS.ncx` and `RECT_FILLETS.h` are both in the folder. On the machine: an operator, or a copy or DNC script that takes `out/*.h` instead of reading stdout, sends a program the run rejected, possibly compiled for another machine file (`JOB_MACHINE_OVERRIDDEN`); nothing in the folder marks it. The same holds, less sharply, for the NCX file left after `ncx check` fails (`NCX_STEP_FAILED`): it stays in the folder and nothing on stdout or in the JSON names it (a control cannot load an NCX file, so it cannot reach the machine as it is). Options:
  - (a) As the SPECs stand: exit ≠ 0 means "take nothing from the folder"; `src/splintercam/apps/cli/AGENTS.md` and the help say so. Relies on discipline.
  - (b) `run_job` gains `strict: bool`: with it, a WARNING withholds the compiled files as an ERROR does (the NCX file is still written, as for an `ncx` failure). `--strict` then means what an operator expects. About 5 NLOC in `job` and a line in REQ-JOB-001, 019 and REQ-CLI-001.
  - (c) The report names what was left on disk: with `--json` a key `files_left` (absolute paths, never for the machine), in the text report one closing stderr line `INFO FILES_LEFT …`. About 10 NLOC in `apps/cli`, a change to REQ-CLI-003, 004 and 006.
  - (d) (b) and the NCX file of a failed run renamed, for example to `RECT_FILLETS.ncx.rejected`.
- Recommendation: (b) and (c): (b) makes a `--strict` run that fails leave no NC program, (c) tells a script what is on disk. Safe default taken: (a), the SPECs as Reviewed; nothing of (b) to (d) is implemented. The pull request names the gap, and until it is answered no program from a run that exited non-zero is taken from the folder.
- Status: Answered 2026-10-27
- Answer: (b) and (c), as recommended (Peter): run_job gains strict: with it a WARNING withholds the compiled files as an ERROR does (the NCX file is still written), and the report names every file left on disk (files_left in --json, one closing INFO FILES_LEFT line on stderr). REQ-JOB-001, 019 and REQ-CLI-001, 003, 004, 006 amended.
