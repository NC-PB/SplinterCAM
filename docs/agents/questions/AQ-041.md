# AQ-041: Where the replay log goes when `splintercam run` meets a kernel failure (spec review of `apps/cli`, plan 0007 step 7)

- Asked: 2026-10-30, plan 0007 step 7 (`apps/cli` implementation, lane I), by the coding agent (headless run)
- Box: 1 (Peter's judgement: what the user sees; the replay input `offset2d` promises; an interface between `job` and `apps/cli`)
- Question: when an `offset2d` kernel call fails, `offset2d` reports `OFFSET_FAILED` and also logs the kernel's input as JSON for replay through `ctx.logger.error` (`src/splintercam/offset2d/_results.py`; `src/splintercam/offset2d/SPEC.md`, "input logged for replay"). `job.default_context` uses the logger `splintercam.job` (`src/splintercam/job/_context.py`), and nothing in `src/` sets a handler, so Python's last-resort handler writes that record to stderr: one long line not in the `<SEVERITY> <CODE> <location>: <message>` form, and with `--json` text on stderr, which REQ-CLI-004 and 006 rule out. The run itself is unaffected: `OFFSET_FAILED` is in the report and the exit code is 1. For the person at the terminal: a JSON dump of curves before the report. For a script: stdout stays one valid JSON object; only stderr is not empty. Options:
  - (a) As now: the record reaches stderr, so the replay input is not lost; REQ-CLI-004 and 006 gain "except a log record of a producer's failure", as the traceback of AQ-012 item 2 already is.
  - (b) The CLI mutes `splintercam` logging (a `NullHandler`, no propagation) until `--debug` exists (SPEC, Later); the replay input is lost for CLI runs.
  - (c) The CLI writes log records to a file next to, not inside, the output folder (for example `<DIR>.log`), and names it in one INFO line; a change to REQ-CLI-003, 004 and 006, about 10 NLOC.
  - (d) A `--log PATH` option now, records to stderr without it as in (a).
- Recommendation: (a) for the slice. It happens only after a kernel bug, the replay input is what the bug report needs, and stdout, which scripts read, stays clean. (c) or (d) with `--debug` and the other commands of the feature map. Safe default taken: (a), nothing changed; recorded in `src/splintercam/apps/cli/DECISIONS.md`, DEC-CLI-003, as provisional.
