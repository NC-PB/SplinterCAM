# AQ-051: Is the point in the NCX file enough to let k ≠ 1 and a ≠ 0 reach a machine?

- Asked: 2026-11-08, plan 0007 (lane P: NCXchange 1e2fd00 and the point words of D-155), by the coding agent after the CNC review
- Box: 1 (Peter's judgement: machine safety, what the setter sees)
- Question: You lifted the refusals of a point k ≠ 1 (AQ-005 item 4) and an axial offset a ≠ 0 (AQ-035) "until NCX has point words", and NCXchange 1e2fd00 has them: the NCX file now says `TOOL_POINT=k TIP_OFFSET=a`, and the machine file maps k to the register. But AQ-035's reason was that "every Z would be output a above the tip with nothing in the program to say so", and the compilers write nothing for a (your answer to NCXchange's drafts, 2026-10-02, (d)). So the Heidenhain `.h`, the Siemens or the Fanuc program on the control shows `TOOL CALL 1`, `D1` or `G43 H1` and Z values a above the tip, and nothing of a. On the machine: with a = 2 and a setter who measures the tip as usual, every Z runs 2 mm high (air cut, scrap); with a program for a = 0 and a setter who measured at a ball's centre, the tip runs a low (gouge or crash); that second case is the same as before this change. There is no setup sheet in the slice. Options: (a) as now in this pull request: the writer also writes `COMMENT="T1 point 2: tool length measured 2.0 mm above the tip"` before the tool block (REQ-NCX-029, Draft; DEC-NCX-022), which every compiler writes as a comment next to the tool change; k and a reach the machine. (b) the NCX words alone are enough; drop the comment. (c) refuse k ≠ 1 and a ≠ 0 again until the setup sheet (AQ-035 (a)) or an NCXchange machine-file comment for a exists.
- Recommendation: (a): it costs one comment line, keeps your lift, and puts the measuring point where the setter reads the tool change; the plan 0007 step 8 dry run checks the register against it. The golden case has k = 1, a = 0, so its program only gains "measured 0.0 mm above the tip". Safe default taken: (a), implemented provisionally (REQ-NCX-029, Draft; `src/splintercam/ncx/DECISIONS.md`, DEC-NCX-022). If you choose (b), the comment goes; if (c), the refusals of `src/splintercam/ncx/DECISIONS.md` DEC-NCX-018 come back.
