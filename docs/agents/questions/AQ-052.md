# AQ-052: The real-`ncx` tests must not pass by skipping on the CI runner that builds `ncx`

- Asked: 2026-11-08, plan 0007 (lane P), by the coding agent after the CNC review
- Box: 1 (CI configuration, a protected path the agent must not edit)
- Question: `tests/ncx/integration/test_real_ncx.py` is now the only check that the point words are valid NCX, that each mill file applies the register of the point, and that a is applied once. It skips when `ncx` is not on the path or `SPLINTERCAM_NCXCHANGE` is unset, so a CI run in which the `build ncx` step silently did not put `ncx` on the path would pass with every one of these checks skipped. The test file now fails instead of skipping when `SPLINTERCAM_REQUIRE_NCX` is set (`test_the_pinned_ncx_is_there_when_required`). The variable must be set where `ncx` is built. On the machine nothing changes; it guards the check that guards what reaches it.
- Recommendation: add one line to the `build ncx` step of `.github/workflows/check.yml`, after the line that sets `SPLINTERCAM_NCXCHANGE` (line 83 at commit b379968):

  ```
            echo "SPLINTERCAM_REQUIRE_NCX=1" >> "$GITHUB_ENV"
  ```

  The step only runs on Ubuntu with a full scope, so macOS and Windows still skip as before. The job and CLI end-to-end tests (`tests/job/golden/test_profile_rectangle_fillets.py`, `tests/apps/cli/test_run_profile_rectangle_fillets.py`) skip the same way and could read the same variable later; not changed here (other lanes). Safe default meanwhile: none possible from this lane; the pull request's CI log is read to confirm the tests ran (they did on 2026-11-08: they failed on the expected `NCX_ROUNDED`, so they were not skipped).
