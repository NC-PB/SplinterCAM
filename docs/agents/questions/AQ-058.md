# AQ-058: When `job` writes the setup sheet (plan 0009, step 4)

- Asked: 2026-11-08, plan 0009 step 1 (SPEC draft, lane S), by the coding agent (headless run)
- Box: 1 (Peter's judgement: what the user finds in the output folder; a change to the Reviewed `src/splintercam/job/SPEC.md`)
- Question: Today `job` writes the NCX file in stage 8 (also when a later stage fails) and moves the compiled files into the output folder only after a clean `ncx` run, and with `strict` not even then when there was a warning (REQ-JOB-019; AQ-040 (b)). When does the sheet appear?
  - (a) **With the compiled files, never without them, never they without it.** After a clean `ncx` run `job` writes `<program name>.setup.html` into the staging folder beside the compiled files and moves it with them; if the sheet cannot be made or written, nothing is moved (a new error, e.g. `JOB_SHEET_UNWRITABLE`); with `strict` and a warning, the sheet is withheld with the program. The sheet names the compiled files, which exist only after `compile`. On the machine side: an operator who finds `RECT_FILLETS.h` always finds `RECT_FILLETS.setup.html` beside it, and a sheet always belongs to a program that compiled.
  - (b) **Always, after stage 6** (the record), even when `ncx` fails: the programmer sees the keep-out numbers early; but a sheet can then lie in a folder with no NC program, or beside an NCX that failed `check`, and could be taken for a valid program's sheet.
  - (c) **On request only** (the feature map's later `sheet` command): an NC program could leave without its sheet, which AQ-035 rules out for other operators.
- Recommendation: (a). It keeps AQ-035's rule in the code: no program without a sheet. The NCX file of a failed run is still written as today, without a sheet. Safe default taken: (a) in `docs/plans/active/0009-setup-sheet.md`, step 4; `src/splintercam/job/SPEC.md` is unchanged until step 4, which brings its SPEC change for review.
