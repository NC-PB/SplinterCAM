# AQ-060: The pocket's drawing: a new import `read_dxf_region` beside `read_dxf_contour` (plan 0008, step 2)

- Asked: 2026-11-08, plan 0008 step 2 (SPEC draft, lane IO), by the coding agent (headless run)
- Box: 1 (Peter's judgement: an interface between modules, and what a user's drawing must look like)
- Question: A pocket needs its outer wall and its islands from one drawing. The profile's import (`read_dxf_contour`) takes exactly one closed contour and refuses several with `DXF_CONTOUR_COUNT`. Plan 0008, step 2 adds a second entry point, drafted as `read_dxf_region(path, layer, unit, ctx) -> Result[DxfRegion]` with `DxfRegion(loops, part_size)` (`src/splintercam/io/SPEC.md`, REQ-IO-031 to 036). `read_dxf_contour` stays as it is.
  - **What the user's drawing must look like.**
    - The pocket goes on a layer of its own, or is alone in the drawing.
    - Every closed outline on that layer is a wall: one outline around the pocket and any number of islands inside it, none inside another.
    - Walls are drawn with LINE, ARC, CIRCLE, LWPOLYLINE or 2D POLYLINE, exactly as for the profile today: same units, same 0.01 mm gap repair, same mirror rule.
    - An island must not touch the wall or another island at an entity end, nor share an edge with it. Draw such an island as part of the wall instead.
  - **What io refuses, and how it is named.** Already in force for the profile, unchanged:
    - An outline that does not close, even by 0.02 mm, stops the import with `DXF_OPEN_CHAIN` naming both free ends. This holds also when the islands alone are closed, so an island is never taken for the pocket.
    - A T or crossing of entity ends stops with `DXF_BRANCH`. For the region, this also covers an island touching the wall at an entity end, provisionally.
    - The other stops: a gap the repair refuses (`DXF_GAP_NOT_CLOSED`), the unit errors, an empty layer (`DXF_LAYER_EMPTY`).
  - **New refusals:**
    - A layer with no closed outline at all stops with `DXF_CONTOUR_COUNT` "no closed chain".
    - Any skipped entity that could be a wall stops the import with `DXF_REGION_INCOMPLETE` (AQ-063).
    - On success io reports "part size 80 x 50 mm, 2 loops", so a missing island shows in the job's messages.
  - **Who judges the shape of the region.**
    - (a) **io hands on every closed chain as it is; the pocket judges.** geometry2d's loop tree nests and orients the loops. Crossing outlines are refused there (`LOOPS_CROSS`). The pocket refuses everything else that is not one outer loop with islands, with `POCKET_REGION` (error, research 04, Method 1 and Test 9): two separate outlines on the layer (two pockets), an island outside the wall, an island inside an island (a boss with a hole, in a pocket). In none of these cases is a program written. The message names the place as a position in mm and the entity index (from the row's source ID, `decode_source_id`). It does not give the CAD's handle, because `DxfRegion` carries no handles.
    - (b) **io runs the loop tree itself and refuses with a `DXF_` code**, naming the entities by index, type and handle, as the profile's import does. The same cases are refused, earlier and with the handles the CAD shows. But the rule then lives in two places (io and the pocket), and io grows by about 20 more lines. The pocket must still check, since its region can come from another source later (STEP faces, features).
    - (c) As (a), but `DxfRegion` also carries each entity's type and handle, so that the job can add them to the pocket's messages: about 10 lines more in io and a wider interface.
- Recommendation: (a), with the names `read_dxf_region` and `DxfRegion`. Positions in mm are enough to find the loop in the CAD; handles can be added later as (c) without changing the rule. Safe default taken: (a) in the Draft rows REQ-IO-031 to 036 of `src/splintercam/io/SPEC.md`; no code until this is answered.
