# RR-023: Where the controller's name for a work offset index can come from

- Date: 2026-11-08; raised by: plan 0009, step 1 (the setup sheet's SPEC draft, lane S)
- Question: Does the pinned NCXchange (machine file keys, `ncx` output or a planned feature) give the name the control uses for the datum `ORIGIN=n`, as the operator sets it (for example the preset table row n selected by cycle 247 Q339 = n on the iTNC 530, G54 to G59 and G54.1 Pn on Fanuc, G54 to G57 and G505 to G599 on the 840D sl)? If not, is a machine-file key or an `ncx info` field for it on NCXchange's roadmap (T-039), and what would the CAM ask for?
- Why it matters: the setup sheet prints "work offset 1 (NCX ORIGIN=1)" (`src/splintercam/setupsheet/SPEC.md`, REQ-SHT-006; AQ-056 item 2). The operator sets the offset on the control, by the control's name. The CAM may not hold a second copy of controller knowledge (D-148), so the name must come from NCXchange.
- What is known: `docs/research/27-machines-and-controllers.md`, controller table, Datum row (the codes per controller; "the UI shows the controller's code") and trap 7 ("datum numbers differ per controller for the same index"); research 27 does not say where the UI would read the code from.
- Provisional choice: the sheet prints the index and the NCX word only (AQ-056 item 2 (a), recommended).
- Status: Open
